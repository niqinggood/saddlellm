# Saddle 原生推理引擎路线

目标是让 Saddle 同时具备服务端并发推理能力和本地模型运行体验。原生执行路径需要自己管理请求、计算预算、KV 与模型生命周期；兼容外部后端可以保留，但不能用外部后端的表现代表 Saddle 原生能力。

## 当前基础与本轮交付

已有原生稠密模型加载、独立生成会话、几何增长 KV、固定微批、等上下文 decode 合批、取消/停止、OpenAI 文本与 SSE 接口、显式开启的融合 decode 算子。不同模型及精度的支持范围见既有验证文档，不能由接口可用推断全部模型可用。

本轮增加 **token 预算调度和 chunked prefill**。开启后，聊天/补全、流式/非流式、greedy/采样都经过同一个原生执行协调器；先处理已就绪的 decode，再以有上限的 prompt 分块推进长请求。取消可在分块之间生效，中间分块跳过词表投影。

这建立了统一调度入口，但 KV 仍由各请求连续存放，decode 仍只合并兼容的等上下文请求；尚未实现分页 KV、任意长度 attention 合批、统一混合 prefill/decode GPU batch 或 CUDA Graph。用法与实测见 [分块调度说明](NATIVE_CHUNKED_PREFILL_20260929.md)。

## 后续按依赖推进

| 阶段 | 要解决的问题 | 交付与验收 |
| --- | --- | --- |
| 1：统一调度入口（本轮已实现首版） | 长 prompt 一次占住执行器，接口采用不同执行通道 | decode 优先、分块 prefill、每轮实际计算 token 预算、统一取消/关闭；验证长短请求交错及全部文本接口 |
| 2：分页 KV 与按显存准入 | 连续 KV 扩容/复制，预算不能反映真实驻留显存 | block pool、block table、分配/回收/引用计数，OOM 前排队/拒绝，取消及故障无泄漏；先单模型稠密 attention |
| 3：任意长度批处理 | 不同上下文难以共享高效 decode，BF16 逐行 Linear 限制吞吐 | 接入支持 block table 的 attention，flatten/ragged 批执行；明确参考数值模式与吞吐模式，各自做质量、延迟、吞吐验收 |
| 4：CUDA Graph 与进一步融合 | 每 token Python 调度和 kernel launch 开销高 | 固定地址执行缓冲、预设 batch 桶、graph capture/replay；先 decode，再评估其他阶段，禁止把 padding 槽算成有效吞吐 |
| 5：本地运行体验 | 模型加载慢、常驻占内存、量化/格式能力分散 | 统一模型清单、拉取/校验、按需加载、keep-alive、空闲卸载、模型切换、量化质量门槛；平台与设备逐项验收 |
| 6：服务运营能力 | 平均 token/s 掩盖尾延迟与资源风险 | 队列/显存/首 token/每 token 指标、负载拒绝和超时，长时间混合负载、恢复与兼容性检查 |

阶段 2、3 必须一起设计接口，不能只有 block allocator 就宣称完成 PagedAttention。CUDA Graph 依赖稳定地址与明确形状，应在执行和缓存接口稳定后推进。本地管理也复用统一引擎；已有 INT8 和生命周期能力先审计整合，不重复另起一套生成循环。

当前优先服务端并发：已有 L20 与同权重比较数据，容易验证调度与批处理是否真正受益。本地易用性随后沿同一执行接口完善，不把全部工作缩减为单请求 token/s。

## 验收口径

- 同设备、权重、dtype、输入/输出 token、缓存策略、思考设置、采样参数比较；分开报告冷启动、预热后单请求、并发和混合长短请求。
- 延迟至少包括 TTFT、ITL、P95；吞吐只统计实际完成 token，并记录错误、取消、内存和服务退出后的资源状态。
- 数值检查区分同执行形状的精确回归、不同形状的误差、生成分叉与任务质量。不能用几条回答相同替代通用质量验收；也不能用不同 dtype/量化的速度宣称无损加速。
- 共享 GPU 上的开发数据与独占设备生产容量分开报告。每阶段保留脚本、原始输出、安装包哈希与运行版本。

方向参考：vLLM 的 [架构](https://docs.vllm.ai/en/latest/design/arch_overview/) 与 [chunked prefill 调优](https://docs.vllm.ai/en/latest/configuration/optimization/)；Ollama 的 [模型驻留、并发与排队说明](https://docs.ollama.com/faq)。参考其能力拆分与验收问题，不由此声称已达到相同性能或覆盖范围。
