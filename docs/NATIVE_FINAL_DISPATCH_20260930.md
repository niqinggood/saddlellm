# 最后一轮原生推理优化：修复收集窗口过期导致的持续拆批

本轮确认并修复了 `NativeStreamBatcher` 密集 decode 调度中的一个具体问题：请求在上一批模型执行期间入队，原来的合批等待截止时间却从入队时计算。执行器再次空闲时，这个截止时间可能已经过去，于是立即发出小批次；刚完成上一批的其他调用者尚未来得及提交下一步。实测会持续形成 B3/B1 交替。

## 最终行为

密集 decode 的收集窗口改为从执行器准备收集下一批时开始。每个窗口只设一次截止时间；其他请求到来时的通知不会延长它，达到目标批大小则立即执行。`batch_wait_ms` 控制这段收集时间，不是整个请求的排队超时；实际线程唤醒仍受操作系统调度影响。

单请求直通、零等待配置、每请求最多一个在途 step、慢客户端背压、取消后等待实际计算结束再清理，以及队列先后顺序继续保留。客户端没有请求下一步时，模型不会额外推进它。本轮修复覆盖 `native_dense_decode` 路径；分块 prefill 使用已有 token 预算调度策略。

没有新增服务开关。已启用 `--native-stream-batching` 的密集 decode 路径使用修复后的窗口；默认数值模式仍为 `compatible`，`throughput` 仍需显式选择。实际批大小变化后，吞吐模式仍可能出现 BF16 舍入差异；未指定独立随机种子的采样输出也会受调度顺序影响。

## 诊断与对照方法

新增 `tools/benchmark_native_dispatch.py`，在同一进程里加载同一个已有本地检查点，分别启动两个临时回环服务。基线调度类来自本轮修改前的源码快照，候选调度类来自当前源码；两个服务使用相同模型执行器、精度、数值模式、采样参数、请求许可与提示词，依次执行，避免同时抢占 GPU。

工具记录每次调度的批大小、请求生成位置、排队年龄、执行 wall time、实际 HTTP usage、首个可见文本延迟、响应时长、文本块间隔、allocated 显存峰值和清理状态。调度时间记录是主机时间，受计时器精度影响；不能当作 CUDA kernel 时间。可见文本块间隔也不是逐 token ITL。

首个诊断负载为四并发、16-token 固定输出。旧调度实际出现 16 次 B1 和 16 次 B3，32 次调度中有 31 次在收集截止时间已过后发出不满批，记录见 `diagnosis.json`。随后三组探索性对照观察到 B4 占比明显增加，配对吞吐中位数提升约 41%，见 `probe_collection_equal.json`；该小样本用于决定是否继续正式验证。

正式命令示例：

```powershell
python tools/benchmark_native_dispatch.py --model outputs/zh_en_small_pretrain_v2_20260923/run_28m/final_model --baseline artifacts/native_final_round_20260930/baseline/saddlellm/runtime/NativeStreamBatcher.py --output artifacts/dispatch_result.json --fixed-length --prompts-file tools/fixtures/native_stream_mixed_prompts.json
```

`--baseline` 执行用户明确指定的可信本地 Python 快照，不应指向不可信下载文件。默认两次预热、七组随机顺序的配对测量。固定长度仅在基准进程禁用 EOS；输出文件记录全部设置和源码指纹。工具成功退出表示请求、清理和源码稳定性检查通过，性能结论仍需检查报告。

## 正式结果

环境：Windows、RTX 4090 Laptop、Torch 2.6.0+cu124、同一 28M 检查点、BF16、投影合并开启、前缀缓存关闭。以下比较基线是**上一轮已优化后的调度**，不是关闭合批，也不是未经优化的旧版服务。

混合长度，四并发、每请求固定 32 输出 token、temperature=0.7、top-p=0.9、throughput 模式，七组配对：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 聚合输出 token/s | 32.54 | 46.17 |
| 首个可见文本 P95 | 623.79 ms | 405.28 ms |
| 响应 P95 | 4027.14 ms | 2852.34 ms |
| 失败请求 | 0 | 0 |

配对 token 速率中位数为 **1.385×**，7/7 更快。正式测量中的调度分布由 B1=224、B3=224，变为 B1=13、B2=6、B3=17、B4=205。该分布是调度提交批大小；模型实际合批次数另见 `/health` 中执行器的 `batch_size_histogram`。候选 allocated 峰值增加约 65 KiB，约 0.05%，不能表述为显存完全不变。

等长四并发，相同采样与输出配置：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 聚合输出 token/s | 35.82 | 54.23 |
| 首个可见文本 P95 | 243.39 ms | 260.07 ms |
| 响应 P95 | 3681.70 ms | 2447.76 ms |
| 失败请求 | 0 | 0 |

配对 token 速率中位数为 **1.501×**，7/7 更快。首个可见文本 P95 增加 **16.68 ms（约 6.9%）**，不能声称所有延迟指标均改善。allocated 峰值增加约 760 KiB，约 0.61%。

单请求对照使用相同的两种调度类，实际均走原有 B1 直通路径：聚合吞吐 **21.13 → 20.95 token/s（约 -0.85%）**，配对速率中位数 **1.002×**、4/7 更快。没有可辨识的吞吐提升，不把小幅波动计为收益；allocated 峰值相同，首个可见文本 P95 为 **61.12 → 64.88 ms**。本轮收益主要出现在可合批的并发负载。

另启进程重复混合长度的七组对照，结果为 **34.24 → 45.64 token/s**；配对速率中位数 **1.340×**，仍为 7/7 更快。首个可见文本 P95 **491.39 → 483.40 ms**，响应 P95 **3880.74 → 2876.24 ms**。因此两次混合长度测量的配对吞吐收益为 **34%～38%**，这是两次测量的范围，不是置信区间。首字改善幅度的波动也保留在报告中。

为检查默认数值模式，另测 `compatible`、greedy、等长四并发：吞吐 **35.52 → 48.52 token/s**，配对速率中位数 **1.386×**，7/7 更快；首个可见文本 P95 **256.53 → 245.76 ms**。逐请求对照的 **28 对输出文本、结束原因和 usage 全部相同**。这只证明本组 greedy 请求的结果一致，不替代所有模型、采样参数和任务质量的验收。

五份最终报告 `final_mixed.json`、`final_equal.json`、`final_single.json`、`final_mixed_repeat.json` 和 `final_compatible_greedy.json` 共包含 **238 个正式测量 HTTP 请求，0 失败**；每组请求结束后 admission、registered、pending、inflight 和 retained cohorts 均已清理。各报告对应同一源码指纹，测量前后及最终核对时均一致。每份四并发报告中每种实现只有 28 个正式请求，P95 属于小样本测量；单请求报告每种实现只有 7 个请求。桌面 GPU 未隔离，未进行长时容量认证。

## 验证记录与交付边界

新增回归用例重现“前一批计算超过收集预算、另一个请求在此期间排队、已完成请求重新提交”的时序。保存的旧调度在该用例上失败，当前调度通过；零等待配置和收集期间关闭服务也有覆盖。针对性回归已通过 103 项，涵盖 CPU/CUDA、兼容/吞吐模式、采样、慢客户端、断连取消、资源清理、流式/非流式及分块 prefill。

最终扩展回归 **1012 passed，0 failed / skipped / error，213.52 秒**，覆盖前述功能和生成、KV、模型生命周期、OpenAI 文本接口、CLI 及 wheel contract 等相关路径。Ruff 指定错误检查、版本一致性、生成函数索引和补丁空白检查通过。跨平台推理 CI 已加入新回归文件；本轮没有运行远程 CI、构建新 wheel 或发布版本。

原始报告、修改前源码快照和测试结果保存在 [本轮验证目录](../artifacts/native_final_round_20260930)，机器可读核对记录见 [verified_summary.json](../artifacts/native_final_round_20260930/verified_summary.json)。源码补丁按本轮快照生成，工作区既有其他改动保留。本轮仅运行临时 loopback 服务，没有重启现有部署。

本轮到调度修复和验证为止。分页 KV、批量变长 attention、CUDA Graph、目标大模型质量及长时容量认证未由本次工作完成；本机 28M 的收益不能外推为目标服务器或其他模型的收益。
