### 1.1 这个模型是怎么来的（模型血缘）

这是一个由 SaddleLLM 在本机**从随机权重开始预训练**出来的 28.3M 参数中英双语基础模型，不是下载某个现成大模型后改名，也不是在 Qwen、Llama 等模型上做 LoRA 微调或蒸馏。它的完整形成过程是：

```text
中英原始语料
  -> 清洗、精确去重、质量过滤
  -> 本地 32K BPE 词表把文本编码成 token
  -> 文档级拼接并打包成定长训练序列
  -> 随机初始化 28.3M 参数 Decoder-only Transformer
  -> Phase 1：约 5 亿 token 广覆盖预训练
  -> Phase 2：约 1 亿 token 高质量语料继续预训练
  -> 按验证集 loss 选择最佳检查点
  -> 导出最终权重、模型配置和词表
```

各部分来源如下：

1. **词表**：正式训练复用了此前 `zh_en_small_pretrain_v2_20260923` 数据准备阶段产出的本地 32,768 词表。它是 Byte-level BPE 词表，特殊 token 为 `<pad>`、`<unk>`、`<bos>`、`<eos>`、`<mask>`。该阶段的资产清单记录了中文 TinyStories、中文 Wikipedia 和英文 TinyStories；各抽样 1,000 条评测时，中英文未知 token 率均为 0，文本往返还原率均为 100%。32K 指 32,768 个 token 编码单元，不是只能认识 32,768 个中文词；中文、英文、数字、标点和未见字符串都可以由单字、子词或字节组合表达。当前 v3 训练没有重新训练词表。
2. **网络结构**：由项目配置定义一个 10 层、隐藏维度 384、6 个注意力头和 2 个 KV 头的 Decoder-only Transformer，然后执行随机初始化。结构采用 GQA、RoPE、SwiGLU、RMSNorm/残差、SDPA、输入输出嵌入共享等现代大模型通用设计。配置中的 `family: qwen` 是架构兼容标签，不代表加载了 Qwen 的预训练权重。
3. **训练目标**：采用标准 Causal Language Modeling。给模型一段 token，让它不断预测下一个 token；预测错误就通过反向传播调整参数。模型的语言能力来自这一步，而不是来自词表本身。
4. **Phase 1 广覆盖预训练**：使用混合中文网页、中文百科、中英文故事和中文诗词，从零训练 `499,712,000` 个 token 位置，先学习文字组合、语法、常见表达和一部分知识。
5. **Phase 2 质量退火**：从 Phase 1 的最佳权重继续训练，不再随机初始化；使用剔除 FineWeb2 网页数据后的高质量语料，以 512 上下文训练 `102,400,000` 个 token 位置，改善中文连贯性、故事结构和长一些的上下文建模。
6. **最终模型选择**：两阶段共训练 `602,112,000` 个 token 位置。训练程序按验证集 loss 保存和选择检查点，最后把最佳权重连同 `saddle_config.json`、`model_blueprint.json` 和 tokenizer 文件一起导出到 `outputs/zh_28m_pretrain_v3/phase2_100m/final_model`。

因此，更准确的定义是：**这是我们独立完成数据准备、结构配置、随机初始化、两阶段预训练和验收的 28M 基础语言模型；网络设计借鉴业界成熟的 Transformer 组件，训练语料来自有各自许可条款的公开数据集。** 它目前是“预训练基座”，还不是经过指令微调、偏好对齐和事实增强的聊天成品。

可追溯入口：Phase 1 配置见 [`zh_28m_pretrain_v3_phase1.yaml`](../configs/zh_28m_pretrain_v3_phase1.yaml)，Phase 2 配置见 [`zh_28m_pretrain_v3_phase2.yaml`](../configs/zh_28m_pretrain_v3_phase2.yaml)，词表配置见 [`tokenizer_config.json`](../outputs/zh_en_small_pretrain_v2_20260923/tokenizer32k/tokenizer_config.json)，早期词表数据清单见 [`corpus_manifest.json`](../outputs/zh_en_small_pretrain_v2_20260923/assets/corpus_manifest.json)。

### 5.2 生成质量抽检

抽检检查点：`checkpoint-10000`。生成参数：temperature 0.75、top-p 0.9、top-k 40、repetition penalty 1.1、seed 42。

| 提示词 | 观察 |
|---|---|
| `中国是一个历史悠久的国家，` | 能生成完整新闻体中文，但出现“中国是世界上最大的贸易组织”等事实和语义错误。 |
| `春天来了，小明和妈妈一起` | 能形成故事段落，但人物关系漂移并反复重复“小明”。 |
| `人工智能是一种` | 句法基本成立，但概念漂移到细胞免疫系统。 |

阶段判断：已经学会中文表面形式和段落结构，但事实、长程一致性和重复控制仍不足，不能作为可用成品。必须完成 Phase 1，并通过 Phase 2 高质量语料退火后再作最终评价。

Phase 1 最终模型复测（最佳权重来自 `checkpoint-30000`）：

| 提示词 | 最终模型表现 |
|---|---|
| `中国是一个历史悠久的国家，` | 新闻体更顺，但仍编造“中国是世界经济最繁荣、规模最大的国家”等内容。 |
| `春天来了，小明和妈妈一起` | 可以继续成段，但人物从妈妈漂移到老师，并反复出现“聊着”。 |
| `人工智能是一种` | 正确接出“技术”，之后仍漂移到经济体制新闻。 |
| `水在标准大气压下达到100摄氏度时会` | 错误回答“燃烧，形成二氧化碳”，暴露基础常识仍不可靠。 |
| `The little girl opened the door and` | 英文故事基本连贯，人物和场景在 64 token 内大致一致。 |
| `床前明月光，` | 生成“云中人影落人肠”，形式像古诗但不是原诗续句。 |

最终判断仍为：Phase 1 训练成功，但中文事实性与篇章一致性尚未达到可用标准；必须继续 Phase 2，并在相同提示词上做前后对比。

## 6. Phase 2：高质量中文退火


### 6.2 过程记录

- 首次 512 数据处理生成 435,632 个训练块和 886 个验证块；tokenization 与打包结果已缓存到 `E:` 数据盘。
- b64 probe 首次使用不同 seed，导致数据缓存 fingerprint 不一致并开始重复预处理；在模型训练前中止，将所有 Phase 2 配置统一为 seed 45 后成功复用缓存。
- 当前 CLI 不允许“YAML 配置文件 + batch/steps 命令行覆盖”混用，因此为 batch 32 和 batch 64 建立了独立、可复现的 probe 配置。后续可将安全覆盖能力作为框架改进项。
- probe 只用于吞吐选择，正式训练始终从 Phase 1 最佳权重重新加载，未继承 probe 更新。

### 6.3 最终生成验收

与 Phase 1 使用相同采样参数和固定 seed：

| 提示词 | Phase 2 最终结果与判断 |
|---|---|
| `中国是一个历史悠久的国家，` | 语言更顺，但仍编造疫情统计和机构信息；事实性未通过。 |
| `春天来了，小明和妈妈一起` | 人物保持为小明和妈妈，形成糖果店小故事并自然结束；比 Phase 1 明显改善。 |

| `水在标准大气压下达到100摄氏度时会` | 采样和 greedy 均错误生成二氧化碳/燃烧；基础常识未通过。 |
| `北京是中国的` | greedy 错误续写为“一带一路”倡议之一；基础常识未通过。 |
| `大熊猫主要生活在` | greedy 错误续写为北极；基础常识未通过。 |
| `The little girl opened the door and` | 英文故事连贯，场景和人物在短文本内基本一致。 |
| `床前明月光，` | 生成格式像诗的原创续句，没有复现原诗；形式能力存在，记忆准确性不足。 |

最终能力边界：该模型已经证明了 28M 中英模型从数据准备、词表、从零预训练、检查点、长上下文退火到导出的完整链路可复现；可用于教学、训练框架回归测试、生成简单中英文故事，以及继续做领域微调。它不是可靠的百科、问答或事实模型，不能用于需要正确知识的生产回答。
